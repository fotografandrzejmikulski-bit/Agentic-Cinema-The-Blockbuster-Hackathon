# StudioSync — Grant Application / Executive Proposal

## Project title
**StudioSync: An Agentic Operations Layer for Real-Time Film Production Recovery**

## Applicant
**Andrzej Mikulski**

## Executive summary
StudioSync is a multi-agent operational intelligence platform for film and media production. It addresses a recurring and expensive problem: when a script, location, cast window, weather event, or supplier constraint changes, production teams must manually reconcile dozens of dependent decisions across schedules, locations, contracts, transport, staffing, and budgets. StudioSync turns that fragmented response into an auditable agentic workflow. Gemini-powered agents decompose a disruption, investigate independent recovery paths in parallel, query production analytics through the official ClickHouse MCP server, and synthesize a ranked recovery plan. A human production lead remains the final authority for consequential changes.

The prototype is deliberately designed as working software rather than a conversational concept. It includes a web application, a production-oriented agent graph, a ClickHouse MCP integration point, reproducible synthetic data, automated tests, containerization, and Cloud Run deployment guidance.

## Problem
Film production is a tightly coupled system. A change to one scene can affect location bookings, crew calls, actor availability, overtime exposure, transport, equipment and the daily burn rate. Existing tools typically record data but do not autonomously reason across these dependencies. The operational gap is not another dashboard; it is the absence of an execution-oriented layer that can transform a natural-language disruption into a defensible decision package.

## Innovation
StudioSync combines three capabilities that are rarely presented as one workflow: (1) multi-agent decomposition of a live production incident, (2) real-time analytical grounding through ClickHouse MCP, and (3) explicit human approval gates for financially or contractually consequential actions. This creates a practical "decision loop" rather than a generic assistant.

## Technology
The implementation uses Google Agent Development Kit (ADK) with Gemini models, FastAPI for the product surface, and the official ClickHouse MCP server as the partner integration. The architecture is compatible with Google Cloud deployment patterns and can be deployed on Cloud Run. The official MCP Streamable HTTP transport is used as the integration contract for remote MCP endpoints.

## Demonstrated workflow
A sample incident — cancellation of Scene 42 due to a storm — produces a ranked set of alternative studios, a quantified budget delta, an explanation of trade-offs, and a list of decisions requiring human authorization. The demo mode is deterministic so judges can reproduce the experience without credentials; a configured deployment switches the analytics layer to ClickHouse MCP at runtime.

## Impact thesis
The economic thesis is straightforward: reduce time spent reconciling operational changes, reduce avoidable production overruns, and shorten the interval between disruption and informed action. The pilot should measure median incident-resolution time, number of manual handoffs, budget-estimate turnaround, and percentage of recommendations accepted without rework. The project does not claim unverified savings as measured facts; these are target metrics for pilot validation.

## Scalability and commercial potential
StudioSync is intended as an orchestration layer that can sit above existing production systems rather than replacing them. The first deployment can use synthetic or imported production data. Later phases can add connectors for scheduling, procurement, location databases and controlled dispatch workflows. The product can serve independent productions, studios, broadcasters and production-service companies.

## Responsible AI
StudioSync is designed around grounded outputs, provenance, least-privilege access, read-only analytics by default, and human authorization for consequential actions. The system explicitly distinguishes data retrieved from tools from estimates generated by models.

## Work plan
**Phase 1 — Prototype hardening:** stabilize evaluation datasets, add trace/evaluation fixtures, validate MCP connectivity, and instrument latency and cost.

**Phase 2 — Pilot:** run the system on 2–3 production workflows, compare against baseline operating procedures, and quantify time-to-decision and budget variance.

**Phase 3 — Productionization:** identity-aware deployment, policy enforcement, enterprise audit logs, connector expansion, and commercialization.

## Success metrics
- 50% reduction in median time from incident report to first actionable recovery plan.
- 30% reduction in manual reconciliation steps for pilot workflows.
- >90% of financial recommendations include machine-readable provenance.
- 100% of state-changing actions require explicit approval in the initial production release.

## Funding request
Grant funding should be used to harden the prototype into a validated pilot: evaluation infrastructure, security controls, production connector development, cloud runtime, and structured pilot delivery. A detailed budget can be attached per the grant program's format; this application intentionally avoids inventing unsupported cost figures.

## Why now
The underlying agent technology has matured enough to make multi-step operational workflows practical, while film production remains highly coordination-intensive. StudioSync targets the gap between general-purpose AI capability and the operational reality of a working production office.

## Applicant statement
I am proposing StudioSync as a practical, measurable application of agentic AI to film production operations. The objective is not to replace production professionals. It is to give them a faster, more auditable way to understand cascading operational consequences and make better decisions under time pressure.
